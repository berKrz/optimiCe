# optimiCe

A runner for metaheuristic optimization algorithms, written in C.

optimiCe runs optimization algorithms against benchmark fitness functions and reports the best solution each run finds. One TOML file describes a whole batch: any number of runs, each with its own algorithm and parameters, repeated over a set number of seeds.

## Highlights

- **Batches.** Several runs in one file, each repeated with its own seed, with shared settings and per-algorithm defaults. See [Configuration](docs/configuration.md#batches).
- **Parallel and reproducible.** Jobs run on every CPU core, and a job's result depends only on its seed: any job can be rerun exactly, with identical output on any machine. See [Seeds and reproducibility](docs/configuration.md#seeds-and-reproducibility).
- **Evaluations counted.** Every run reports how many fitness evaluations it used, the fair cost measure for comparing algorithms. See [Evaluations](docs/fitness.md#evaluations).
- **Early stopping.** An iteration budget, plus optional stops on reaching a target fitness or after a stretch without improvement. See [Stopping](docs/configuration.md#stopping).
- **Flexible search spaces.** Bounded or unbounded domains, a separate initialization range, and a choice of boundary handling. See [Domain and initialization range](docs/configuration.md#domain-and-initialization-range).
- **Results you can trace.** A CSV results file recording the commit and the configuration that produced it, with exact values. See [Results file](docs/output.md#results-file).
- **Checked up front.** Every configuration error is reported at startup, naming the file, section and key, before anything runs.
- **Interactive mode.** Step through a run one iteration at a time and watch the population move.

## Build

optimiCe depends on [tomlc17](https://github.com/cktan/tomlc17) for TOML parsing. With it available:

```bash
make
```

produces the `optimice` binary in the repository's root. The Makefile finds tomlc17 through `pkg-config`, and falls back to a plain `-ltomlc17` when `pkg-config` can't find it. `make test` runs the test suite, which also needs [Criterion](https://github.com/Snaipe/Criterion); see [Tests](CONTRIBUTING.md#tests).

**With Nix**, the flake provides tomlc17 and the whole toolchain: `nix develop` enters a shell to run `make` from, and

```bash
nix build    # binary at ./result/bin/optimice
```

builds the binary directly.

**Without Nix**, build and install tomlc17 from upstream first:

```bash
git clone https://github.com/cktan/tomlc17
cd tomlc17
make
sudo make install    # installs to /usr/local by default
```

If you install it under a non-default prefix, point `pkg-config` at it when building optimiCe, e.g. `PKG_CONFIG_PATH=$HOME/.local/lib/pkgconfig make`.

## Quick start

A configuration file with a single run:

```toml
[common]
n_dims     = 2
fitness    = "sphere"
domain_min = -5.0
domain_max = 5.0
iterations = 100
seed       = 42

[[run]]
algorithm  = "pso"
swarm_size = 30
w          = 0.7
```

```bash
./optimice -f quickstart.toml
```

prints the best fitness at every iteration, then the result:

```
==================================================
=== Final Result =================================

Best solution:
   pos: [  -0.000  -0.000 ]
   fitness = 7.872174776306589e-11

Iterations: 100
Evaluations: 3030
Algorithm: pso    Seed: 0x0000002a
==================================================
```

[`example.toml`](example.toml) is a fuller example: a batch with every algorithm, repeated over five seeds.

## Usage

```bash
./optimice -f FILE [options]
```

| Flag        | Long form         | Description                                                                 |
|-------------|-------------------|-----------------------------------------------------------------------------|
| `-f FILE`   | `--config FILE`   | Path to the TOML configuration file (required)                              |
| `-o [PATH]` | `--output [PATH]` | Also write the results to a CSV file (see [Results file](docs/output.md#results-file)) |
| `-d`        | `--dump-config`   | Print the resolved configuration and exit                                   |
| `-i`        | `--interactive`   | Pause after each iteration; the batch must be a single job                  |
| `-l`        | `--list`          | List the algorithms and fitness functions, with each function's limits      |
| `-h [ALG]`  | `--help [ALG]`    | General help, or an algorithm's fields if `ALG` is given                    |

Short options work in either case: `-F` is `-f`.
